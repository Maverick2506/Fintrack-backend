# Fintrack-backend

Express 5 + Sequelize 6. Production runs on **Render** with **Neon Postgres**. Local and test use **SQLite**. Timezone for all "today" logic: **America/Toronto**.

## Run and test
- Install: `npm ci` (Node 22)
- Start a **test** server in a second terminal first. `npm test` refuses to run against anything else:
  `NODE_ENV=test ALLOW_DEV_BYPASS=true node server.js`
- Then: `npm test` (Gemini unit tests + the integration suite in `test/runTests.js`)
- Tests use `test-database.sqlite`; local dev uses `local-database.sqlite`. Never point tests at `DATABASE_URL`.
- CI (`.github/workflows/ci.yml`, job `test`) does the same on every PR.

## Rules for any change
- **Money:** every balance change goes through `services/accountBalanceService.js` (`adjustAccountForTransaction`, the `balanceApplied` flag). Never update `initialBalance` directly in a route.
- **Card and debt payments** are `TRANSFER`s, not spending. Card purchases are `EXPENSE`s from the card.
- **Schema:**
  - new **tables** go in `models/` (created by `sync()`);
  - new **columns/indexes** use guarded `queryInterface` calls in `server.js` `initialize()`;
  - one-off data fixes are guarded by a `Setting` flag;
  - no ENUM changes.
- **Validation:** every write route uses `validateBody(schemas.X)` (zod, `middleware/validate.js`); `:id` params are UUID-checked.
- **Auth:** every route needs `authMiddleware`, except health, login, the cron routes (`CRON_SECRET`) and the export feed (feed key). The route-auth test in `test/runTests.js` fails if a new route is left open.
- **Recurring series:** generated by `routes/recurring.js`, which follows the newest row of a series (`recurringGroupId`, unique per date). Run generation **after** a request's transaction commits, never inside it.
- **Forecast / Safe to Spend:** `services/forecastService.js` is the single source; AI prompts and the digest use it.
- **Gemini:** `routes/gemini.js`. Model names come from `GEMINI_MODEL_*` env vars (defaults `gemini-3.5-flash`). The server owns all numbers; the model only writes text.
- **Tests:** add or extend a numbered suite in `test/runTests.js` for every fix. A bug fix needs a test that fails without it.

## Pull requests
- Branch from `main`; never push to `main`. One PR per change; title says what changed for the user.
- In the PR description, list any **Render env var** or **one-time migration** the change needs.
- Don't merge. Maverick merges after review and green CI.
